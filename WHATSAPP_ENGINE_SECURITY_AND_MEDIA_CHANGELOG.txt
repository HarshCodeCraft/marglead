1. BACKGROUND & PROBLEMS IDENTIFIED (KYU CHANGE KAR RAHE HAIN)
--------------------------------------------------------------------------------

PROBLEM 1: Campaign Photos Corrupted & Sent as "Invoice.pdf"
- Issue: When a user uploaded an image (.jpeg, .png) for a Campaign or Direct
  Broadcast, the recipient received a file named "Invoice.pdf (222 KB)" which
  could NOT be opened on their phone ("Corrupted PDF error").
- Root Cause:
  1. api/whatsapp_web_engine.php passed all media as 'pdf_url'.
  2. The Node.js Baileys engine on the Oracle server (/var/www/html/whatsapp_engine/index.js)
     had hardcoded:
     `if (pdf_url) { document: { url: pdf_url }, mimetype: 'application/pdf', fileName: 'Invoice.pdf' }`
  3. WhatsApp treated the JPEG binary bytes as a PDF document. Adobe Acrobat / Drive
     PDF viewer rejected the JPEG headers, failing to open.

PROBLEM 2: Cross-User Fallback Risk (Catastrophic Multi-User Data Leakage)
- Issue: When User A's WhatsApp account was restricted or disconnected by WhatsApp,
  the campaign did NOT halt. Instead, it picked User B's / another connected client's
  WhatsApp number from the database and started blasting campaign messages from
  that other user's number!
- Root Cause:
  In api/campaign-api.php line 29:
  `SELECT * FROM merchant_waba_settings WHERE web_api_session_status = 'connected' ORDER BY id DESC LIMIT 1`
  When User A's session was disconnected, this query fetched another merchant's
  connected session and hijacked their phone number!

2. EXACT UPDATES & FIXES APPLIED (KYA UPDATE HUA HAI)
--------------------------------------------------------------------------------

UPDATE A: Hostinger PHP Layer (api/campaign-api.php & api/whatsapp_web_engine.php)
1. Strict User Isolation:
   - Deleted the cross-user fallback query completely.
   - getActiveWabaConfig() ONLY returns the specific user's own config.
   - If that user's session is disconnected, it returns null and NEVER looks
     at any other user's row.
2. Pre-Flight Verification & Emergency Circuit Breaker:
   - Before a batch starts, if the account's WhatsApp is disconnected, the campaign
     pauses immediately (0 messages dispatched).
   - If WhatsApp returns a disconnection / restriction error during dispatch, the
     loop halts instantly, pauses the campaign, and prevents touching any other account.
3. Media Separation:
   - Images are strictly passed as 'image_url' with 'media_type: image'.
   - Marg ERP bills are strictly passed as 'document_url' / 'pdf_url' with 'Invoice.pdf'.

UPDATE B: Oracle VPS Engine Layer (/var/www/html/whatsapp_engine/index.js)
1. Pure Stateless Gateway (0 Disk Storage on Oracle):
   - Oracle VPS does NOT store any images, PDFs, or bills on disk.
   - Media URLs hosted on Hostinger HTTPS are streamed directly to WhatsApp.
   - Oracle RAM usage stays minimal (~15-20%), eliminating Out-Of-Memory (OOM) crashes.
2. Smart Dual-Router (Photo vs Marg Bill):
   - IF media extension is image (.jpg, .jpeg, .png, .webp) OR media_type == 'image':
     Dispatches as native WhatsApp Photo (`{ image: { url: rawMedia }, caption }`).
     Opens directly in WhatsApp chat gallery!
   - IF media is Marg ERP Bill / Document (.pdf):
     Dispatches as native WhatsApp Document (`{ document: { url: rawMedia }, mimetype: 'application/pdf', fileName: 'Invoice.pdf' }`).
     Opens smoothly in phone PDF viewers!
3. Strict Session Check (No Guessing):
   - If user_id is missing -> Rejects with 400 MISSING_USER_ID.
   - If user_id session is not connected -> Rejects with 503 SESSION_NOT_CONNECTED.
   - Returns clear exact error reasons. Never falls back to another user.
4. Auto Phone Sanitizer:
   - Auto-adds country code 91 for 10-digit Indian numbers.
   - Strips leading zeros (e.g. 09876543210 -> 919876543210).
