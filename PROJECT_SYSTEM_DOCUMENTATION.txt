1. SYSTEM OVERVIEW & ARCHITECTURE STACK
================================================================================
The Marg ERP CRM is built on a clean, high-performance, modular PHP architecture
designed to manage end-to-end customer lifecycles, active CRM accounts, old client
directories (28 headers), support tickets, sales pipelines, installations, user
trainings,Quotations, and financial invoices.

Core Technologies Used:
------------------------
- Core Backend: PHP 8.x (Native Modular MVC Architecture)
- Database: MySQL 8.x / MariaDB via PHP Data Objects (PDO)
- Frontend Logic: JavaScript (ES6+ Native Async/Fetch API)
- Styling & UI Design: Vanilla CSS3 utilizing CSS Custom Properties (CSS Variables)
  supporting sleek Dark Mode (#0b0f19 / #121826) and Glassmorphism effects.
- Icons: Lucide Icon Library (v0.263)
- Fonts: Google Fonts ('Outfit', 'Inter', Monospace)
- File Parsers: PHP ZipArchive & SimpleXML (Native XLSX parsing without Composer)

Architecture Pattern:
---------------------
- Single Entry Router: index.php routes module views via ?page=...
- Includes:
  - includes/config.php : Global system settings, timezone, sessions & security headers.
  - includes/db.php     : PDO Database connection setup.
  - includes/header.php : Sidebar navigation, header bars, user roles, top notifications.
  - includes/footer.php : Global modal containers, script inclusions, Lucide initializer.
  - includes/mailer.php : SMTP Email sending engine & logs.

2. DATA SECURITY & HARDENING ENGINE
================================================================================
The system enforces multi-layered enterprise security against web vulnerabilities
such as SQL Injection, Cross-Site Scripting (XSS), Clickjacking, and Session Hijacking.

A. SQL Injection Prevention (100% PDO Prepared Statements)
----------------------------------------------------------
Every database operation (SELECT, INSERT, UPDATE, DELETE) uses PDO prepared statements
with bound parameter placeholders (?) or named parameters (:param). Raw SQL query
string concatenation of user input ($_GET, $_POST, $_COOKIE) is strictly prohibited.

Example PDO Prepared Query:
  $stmt = $pdo->prepare("
      SELECT * FROM client_directory 
      WHERE (party_name LIKE ? OR customer_id LIKE ? OR mobile LIKE ?)
        AND LOWER(party_status) = ?
      ORDER BY id DESC LIMIT ? OFFSET ?
  ");
  $stmt->bindValue(1, '%'.$search.'%', PDO::PARAM_STR);
  $stmt->bindValue(2, '%'.$search.'%', PDO::PARAM_STR);
  $stmt->bindValue(3, '%'.$search.'%', PDO::PARAM_STR);
  $stmt->bindValue(4, strtolower($status), PDO::PARAM_STR);
  $stmt->bindValue(5, $limit, PDO::PARAM_INT);
  $stmt->bindValue(6, $offset, PDO::PARAM_INT);
  $stmt->execute();

B. Cross-Site Scripting (XSS) Sanitization
------------------------------------------
All dynamic text variables rendered into HTML content, input attributes, tables, or
modal fields are sanitized using htmlspecialchars($val, ENT_QUOTES, 'UTF-8').

Example XSS Output Sanitization:
  <strong class="text-main"><?php echo htmlspecialchars($r['party_name']); ?></strong>
  <input type="text" value="<?php echo htmlspecialchars($search_query, ENT_QUOTES, 'UTF-8'); ?>">

C. URL & Input Parameter Filtering
----------------------------------
- Router Whitelisting: index.php matches ?page= against an approved array of modules.
  Arbitrary path parameters or directory traversal attempts (?page=../../etc/passwd)
  are caught and redirected safely to the dashboard.
- Type Casting: Integer parameters (page numbers $p, page limits $limit, record IDs)
  are explicitly cast using intval() or max().

D. HTTP Security Headers
------------------------
Enforced globally in includes/config.php before output buffering:
  - X-Frame-Options: SAMEORIGIN (Prevents Clickjacking iframe attacks)
  - X-Content-Type-Options: nosniff (Blocks MIME-type spoofing)
  - X-XSS-Protection: 1; mode=block (Activates browser XSS filtering)
  - Referrer-Policy: strict-origin-when-cross-origin (Protects sensitive headers)

E. Role-Based Access Control (RBAC) & Session Hardening
-------------------------------------------------------
- Unauthenticated requests redirect automatically to auth/login.php.
- User status (Active, Inactive, Suspended) is checked against the database on
  every page load; deactivated users are instantly logged out.
- Restricted administrative operations (Client Directory Bulk Upload, System Settings,
  Role Permissions) enforce access checks using hasAccess() or $is_admin checks.

5. BULK SPREADSHEET UPLOAD METHOD (NATIVE XLSX & CSV PARSER)
================================================================================
Location: modules/clients.php -> parseClientXLSX()

Overview:
---------
Allows users to bulk upload Excel (.xlsx) and CSV files containing up to 10,000+ client
rows directly into the client_directory database without requiring external Composer
libraries (such as PhpSpreadsheet).

Native XLSX Parser Implementation Details:
------------------------------------------
1. Standard Excel .xlsx files are ZIP archives containing XML documents.
2. PHP's ZipArchive extractsxl/sharedStrings.xml to build a text lookup index.
3. It parses xl/worksheets/sheet1.xml using SimpleXML to read row coordinates (e.g. A1, B2).
4. Coordinates are converted to 0-indexed column positions. Shared string indexes (c t="s")
   are mapped back to their original text values.

Header Auto-Mapping & Flexibility:
----------------------------------
The importer normalizes header strings by stripping spaces, special characters, and case:
  $cleanH = strtolower(trim(preg_replace('/[^a-zA-Z0-9]/', '', $headerName)));

Key mappings accept flexible header names:
  - Customer ID: 'CUSTOMER ID', 'customer_id', 'customerid', 'cust_id'
  - Party Name: 'Party Name', 'party_name', 'party'
  - Mobile: Handles Excel scientific notation (e.g. 9.34E+09 -> 9340000000)

Duplicate Customer ID Handling:
-------------------------------
- Option A ("update"): Overwrites existing database fields if Customer ID matches.
- Option B ("skip"): Ignores duplicate rows and retains existing records.

8. LIVE BACKGROUND DATA AUTO-SYNC SYSTEM
================================================================================
Location: assets/js/main.js

Overview:
---------
Ensures that the displayed table records and KPI summary cards update automatically
in the background without requiring manual browser page reloads (F5).

How It Works:
-------------
1. Polling Loop: Runs every 1.5 seconds (1500ms) calling autoSyncPageData().
2. Silent Fetch: Executes an asynchronous fetch(window.location.href) with header
   X-Requested-With: XMLHttpRequest.
3. DOM Parsing & Targeted Replacement:
   - Uses DOMParser to extract .table-responsive (data tables) and .grid-4 (KPI cards).
   - Replaces innerHTML ONLY if the content has changed.
   - Re-initializes Lucide icons and column visibility preferences.

Form Protection Guard (isUserFillingForm()):
--------------------------------------------
Guarantees 0% disruption to users/admins while filling out forms:
- Checks if any modal window is open (.modal-overlay.open).
- Checks if any input element (<input>, <textarea>, <select>) is currently focused or active.
- Checks if the user is actively typing.
- If ANY condition is true, background updates are PAUSED immediately, preventing form
  inputs from ever being cleared, reset, or interrupted.

window.alert = function(msg) {
    if (!msg) return;
    let container = document.getElementById('crm-global-toast-container');
    if (!container) {
        container = document.createElement('div');
        container.id = 'crm-global-toast-container';
        container.style.cssText = 'position:fixed; bottom:24px; right:24px; z-index:99999; display:flex; flex-direction:column; gap:8px; max-width:420px; pointer-events:none;';
        document.body.appendChild(container);
    }
    const toast = document.createElement('div');
    toast.style.cssText = 'background:var(--bg-card,#1e293b); color:var(--text-main,#f8fafc); border:1px solid var(--primary,#3b82f6); padding:12px 18px; border-radius:10px; box-shadow:0 10px 30px rgba(0,0,0,0.5); font-size:0.85rem; font-weight:600; opacity:0; transform:translateY(10px); transition:all 0.3s ease; pointer-events:auto;';
    toast.innerHTML = '<span>' + String(msg).replace(/\n/g, '<br>') + '</span>';
    container.appendChild(toast);
    setTimeout(() => { toast.style.opacity = '1'; toast.style.transform = 'translateY(0)'; }, 10);
    setTimeout(() => { toast.style.opacity = '0'; toast.style.transform = 'translateY(10px)'; setTimeout(() => toast.remove(), 300); }, 3500);
};
